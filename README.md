# 狼月 Wolf Moon — README

> **版本**：`v0.0.1`（M＝Mobile 手機優先；線上多人版，保留本機試玩）
> **類型**：3–6 人線上卡牌遊戲 / 手機優先 UI
> **技術棧**：React 18（CDN）+ Babel Standalone + Tailwind CSS（CDN）+ FontAwesome + Firebase Auth / Realtime Database
> **語言**：繁體中文
> **架構**：單一 HTML 檔案自包含 (Single-File Architecture)
>
> 每次改版請同步更新：首頁（名稱／房間）與牌桌頂部狀態列的版本字串（格式 `vX.Y.Z`）。

---

## 1. 專案概述

本專案是《狼月 Wolf Moon》桌遊的瀏覽器版，支援 3–6 位真人與 AI 混合遊玩，也保留本機試玩。線上流程分為名稱／建立或加入房間、等待大廳、遊戲牌桌；房主可調整 AI 數量並開始遊戲。UI 以手機直式為主，桌面端自動置中顯示。全套 30 張角色牌、3 張月亮牌。

> **線上模式限制**：目前採用輕量的用戶端同步，遊戲狀態（包括所有玩家手牌及私密紀錄資料）會寫入 Realtime Database，房間成員可讀取完整狀態。介面會依玩家篩選秘密資訊，但這不是資料庫存取控制，也不能防止玩家透過瀏覽器工具或 RTDB 讀取原始資料。因此本版只適合休閒遊玩；正式競技需改用伺服器權威流程，並把每位玩家的私密資料分開儲存及設定規則。

## 2. UI 介面

- 手機優先直式佈局，桌面端自動置中並加外框。
- **版本顯示**：首頁（名稱／房間）與牌桌頂部狀態列皆顯示版本字串（格式 `vX.Y.Z M`，M＝Mobile）。
- 頂部狀態列(A區)：版本號、動態開關、速度按鈕 0.5x、規則按鈕、紀錄按鈕（由左至右：動態 ➜ 0.5x ➜ 規則 ➜ 紀錄）。速度按鈕為放慢（只保留 0.5x）：AI 出牌等待、月亮牌停留、效果動畫都依倍數拉長（0.5x＝兩倍時間）；再點一次同一顆回到正常速度；回放紀錄動畫不受影響。
- 玩家頭像區(B區)：最多 6 位玩家、存活／出局狀態；B 區不可左右滑動，玩家依房間人數平均分寬。輪到誰只用亮框表示（綠色發光外框）。各玩家框框左上角固定留一排高度 11px 的狀態列（不換行、超出裁切）：勝場月亮、面前牌張數、生效中、守護、女巫標示。點擊頭像可檢視該玩家面前的牌。**出局玩家仍可觀看動畫、檢視紀錄，並在局末準備下一局。**
- 中央戰場(C區)：動態中控廣播與提示（頂部的廣播條預設隱藏，由 A 區「動態」按鈕開關）、場上打出卡牌展示動畫。左上角月亮進度計數器 (x/3)，右上角「備用牌 N」「暗牌 N」「牌庫 N」。
- 底部手牌區(D區)：手牌卡片、右側操作按鈕「抽一打一」「拿一還一」。沒有「確定出牌」按鈕；拖曳或雙點出牌。出牌後（含被動牌／保鏢等）會鎖定操作，直到換人，避免再按「抽一打一」。

### 2.1 效果動畫

- 公開動畫經 `gameState/fxEvent` 推送給房間成員；**每個客戶端獨立顯示、排隊與關閉**。
- **本機排序佇列**：若本機已有動畫在播或停在最後一格，新動畫會排入佇列，不會直接蓋掉目前畫面。
- 一般動畫播完停在最後一格並顯示「👆 點一下繼續」；**必須點擊**才關閉目前動畫並播放佇列中的下一個。
- **點擊只影響本機**，不會替其他玩家略過，也不會阻塞 AI／回合推進。
- 遊戲流程（AI、換人、額外回合）只等待動畫的**播放時長**（`whenFxDone`），**不等待**玩家點擊；有人一直不點，只會讓自己的疊層留著或繼續排隊，不會卡住其他人。
- **全屏動畫（月亮升起、狼月咬鏡頭、吸血鬼降臨）**：對局中**不可提前跳過**，播完停住等點；從行動紀錄回放時可點一下離開。
- 安全網：單一動畫顯示超過原定長度 + 10 秒仍未關閉時，本機可強制解除，避免卡死畫面。
- 從行動紀錄「回放」：點一下即可離開；回放不影響對局狀態與佇列權威流程。

### 2.2 公開／私密結果

- **比大小（酒保／小女孩）**：無論出局或平手，動畫對所有玩家公開；平手不公開雙方手牌數值。
- **掘墓人奪取**：全公開（誰、從誰面前、拿走哪一張）。
- **稅務官／審判官**：命中出局與審查／審判失敗皆公開；出局時一併公開手牌。
- **扒手**：公開顯示「誰與誰交換」；**指定的兩位玩家與出牌者**可另看交換了什麼牌（私密行）。
- **先知**：公開播放秘密檢視動畫（不揭露牌面）；牌面結果僅先知在紀錄/動態私密行可見；他人只見「秘密檢視完成」。
- 仍維持私密的：小偷／扒手交換內容（僅雙方可見換出／換入）、拿一還一抽到的暗牌內容、自己抽到的牌等。
- **醉漢**：每位參與者本機依 `drunkMeta` 個人化「換出／換入」；公開只顯示重發摘要。同步時不廣播 `mine`，避免全員看到出牌者的牌面。
- **拿一還一公開動畫**：其他人可見「誰、哪一格暗牌被拿起並放回」；牌面只給執行者。
- **煉金術士復活**：淘汰動畫先播，再 queue「棄掉面前煉金術士 → 復活」動畫（`kind: alchemist`）。

### 2.3 其他 UI

- **動態廣播**：預設開啟（可手動關閉）。
- **行動紀錄**：與本機玩家有關的條目在**右側加黃色邊**；出局紅底、復活綠、其餘紫邊。
- **最終比點數／乞丐之王結算動畫**：不可跳過、無自動關閉；播完才能點擊繼續，且每位玩家只影響自己的本機畫面（`scoreDoneKeysRef`）。勝利視窗要等**本機**點擊關閉此動畫後才出現（以 `winnerInfo.scores.fxKey` 對應動畫）。
- **勝利視窗**：等終局動畫（狼月/吸血鬼/比點）播放時長結束後出現；不等 sticky 點擊。非房主先收到 gameOver 時會寬限等待 fxEvent，避免未播狼月就跳出結算。
- 結算後的牌桌（攤牌模式）：C 區改為「全部攤牌」面板；勝利者標 🏆；可「查看結算」重開勝利視窗。
- **下一局防誤跳**：房主開新局（含 transaction）必須 `gameState.gameOver === true`；對局中或非結算狀態不可準備；玩家若發現自己有殘留的 `nextReady` 旗標（本局未結束）會自動清除。
- **下一局**：線上模式須**所有真人玩家**（含出局者）都按下「準備下一局」後才會開新局（按鈕顯示 `已準備 x/n`）；AI 不需準備。本機試玩一人按即可開始。準備狀態寫在 `nextReady/{uid}`（玩家本人可寫）；房主偵測全員準備後升 `round`、清 `gameState` 與 `nextReady`。

### 2.4 大廳（第 2 頁）

- 房間號碼為 **6 位純數字**（100000–999999）。
- 房主的 **AI ± 調整固定在玩家名單上方**，不隨 AI 增減下移；名單區可捲動。
- 開始遊戲按鈕在名單下方。

### 2.5 互動彈窗

- **只剩一個可選目標**：仍進入確認彈窗，預填唯一目標並標示「唯一可選」，**不再選頭像**；需按確認才發動。
- **無可選目標**：直接結算為「沒有任何效果（沒有可選擇目標）」，並播無效果／置於面前動畫。
- **村民**：數值 0–10 **按鈕列表**單選（非下拉選單）。
- **刺客**：與扒手相同邏輯——同一組 0–10 按鈕，第 1 下＝數值 1、第 2 下＝數值 2，再點同一數值取消，角標顯示 1／2；兩個都選好才能確認。
- **扒手**：最多 6 個頭像（可含自己）；第 1 下＝目標 1、第 2 下＝目標 2，再點同一人取消，角標 1／2。

## 3. 遊戲狀態管理

- 每局 3–6 位真人與 AI 混合玩家；本機試玩維持 1 位人類 + 5 位 AI。
- 牌庫建立、洗牌、抽牌、月亮牌補充。
- 手牌、面前牌區（arena）、出局狀態追蹤。
- 回合切換與存活玩家輪轉。
- **換人序號 `turnSeq`**：每次 `proceedToNext` 換人時遞增（`turnSeqRef`），並隨快照寫入 `gameState.turnSeq`。接收快照時，僅在「本機仍握有行動權」（本人真人回合，或房主且本機當前為 AI 回合）且遠端 `turnSeq` 較舊、或同序但 `sourceUid` 非本人時，才跳過套用、只跟上 revision；**AI 回合以房主快照為準**，Guest 不得因本機序號較大而拒絕房主的月亮／復活連鎖。**不可再用 `currentTurnIndex` 大小比較新舊**（座位序號繞回 0 時會誤判）。新局時 `turnSeqRef` 歸零；本機尚無牌局（`players` 為空）時一律套用快照。
- **發布權限（單一權威）**：房主恆可寫入 `gameState`；Guest 僅在「當前行動者為自己且非 AI」時可寫入。已移除以 `lastActorUid` 在換人後繼續發布的路徑，避免 Guest 獨跑 AI／月亮／煉金術士連鎖造成分叉。
- **revision 同步**：`gameState.revision` 遞增；新局 `gameState = null` 時非房主重置 revision 並清空桌面狀態（手牌、牌庫、中央暗牌、C 區等），且禁止把上局狀態寫回 RTDB；房主負責 `initGame` 並寫入新狀態。線上尚未收到牌局時顯示「正在同步牌局…」，不誤顯上局手牌。

## 4. 回合流程（部分）

- 換人／額外回合：`proceedToNext` 同時遞增 `turnSeq` 與 `aiKick`；額外回合座位序號不變，AI 靠 `aiKick` 重新驅動。線上發布快照一次只有一個 transaction，被中止會自動重試。
- 抽牌階段：抽一打一 / 拿一還一。
-「拿一還一」：選 1 格暗牌拿走，再拖曳 1 張手牌放回同一格，放回後結束回合。
- 月亮牌：翻開展示並計數 +1，不給額外回合；第 3 張月亮時手握狼人者立刻獲勝（叛徒連帶）。
- 出牌方式：拖曳手牌到 C 區或快速雙點；長按可放大檢視牌面。
- **被動牌／保鏢／僕人（含煉金術士）**：打出後 `advanceAfterPassive`——畫面可 sticky 等人點，流程只等動畫時長後換人；換人前保持操作鎖定。另有安全網（約 8 秒）強制換人，確認打出煉金術士等被動牌後不會卡死。
- 其餘角色結算、暗牌追蹤、先知／醉漢私密資訊等，見完整角色表。

## 5. AI 系統（部分）

- AI 自動抽牌／拿牌／出牌；簡單策略優先安全牌、避免市長與狼人。
- AI 出牌後以動畫播放時長推進（`whenFxDone`），不因其他玩家未點動畫而卡住。
- AI 約 25% 機率使用「拿一還一」。
- 出牌前思考等待較短；出牌後多留緩衝，方便玩家看完效果動畫。
- 被動牌（含煉金術士、商人、叛徒、陰謀家、科學怪人、乞丐之王等）打出後固定結算並換人；`advanceAfterPassive` 依動畫時長推進，並有逾時安全網，避免卡死。

## 6. 牌庫設定與三層結構

- 全套 30 張角色牌；狼人先抽出洗入上層；發牌用其餘 29 張，每人 1 張手牌；保留 2 張備用、3 張中央暗牌。
- 三層：下層洗入第 3 月亮、中層第 2 月亮、上層洗入狼人且孤狼月亮在最底，確保出現順序為狼人 → 孤狼月亮 → 嘯狼月亮 → 狼人月亮。

## 8. 勝負結算條件優先順序

1. 唯一存活者  
2. 吸血鬼條件（面前兩張 ≥7）  
3. 狼月降臨（第 3 月亮或之後拿一還一／守夜人留下狼人；叛徒連帶）  
4. 牌庫耗盡比分（含乞丐之王）  
5. 3-4人局勝場月亮累計 **2 勝** 贏得整場  ,  5-6人局累計**3 勝** 贏得整場

## 9. 檔案結構

```
index.html
├── head：Tailwind、FontAwesome、Firebase CDN、自訂 CSS
└── body：#root、React / ReactDOM / Babel、單一 <script type="text/babel">
    ├── 常數、BASE_CARDS_DEF、MOON_CARDS、deriveFx、FxOverlay
    ├── App
    │   ├── presentLocalFx / startFx / skipFx / whenFxDone
    │   ├── fxQueueRef（本機動畫佇列）
    │   ├── fxEvent 訂閱（線上公開／私密動畫）
    │   ├── nextReady 準備下一局（玩家寫入、房主升局）
    │   ├── advanceAfterPassive（被動牌鎖定至換人）
    │   └── 回合 / AI / 彈窗 / JSX
database.rules.json   # Firebase RTDB 規則（含 nextReady）
```

### Firebase 與部署

1. Firebase Console 建立專案並新增 Web App。  
2. Authentication → Sign-in method 啟用 Anonymous。  
3. Realtime Database 匯入規則並發布（見下方）。  
4. 將 Firebase 設定填入檔案內 `FIREBASE_CONFIG`。  
5. 部署至 Vercel（或任意靜態託管）。

### Realtime Database 規則重點

在 `rooms/$roomCode` 下需允許：

- **房間根寫入**：僅房主（`hostUid`）  
- **players/$uid**：本人加入大廳  
- **aiCount / status / hostUid / round / gamePlayers**：房主  
- **gameState**：房間內玩家可寫（revision 同步）  
- **nextReady/$uid**：房間內玩家寫入自己的準備狀態  

範例片段（併入既有 rules）：

```json
"nextReady": {
  "$uid": {
    ".write": "auth != null && auth.uid == $uid && data.parent().parent().child('players').child(auth.uid).exists()",
    ".validate": "newData.isBoolean()"
  }
}
```

## 10. 效果動畫實作對照

| 項目 | 行為 |
|------|------|
| `presentLocalFx(f)` | 顯示一筆；非 sticky 播完可自動推進佇列 |
| `startFx(f, publicFx?)` | 更新 `fxUntilRef`；推送 `fxEvent`；本機忙則排隊、否則播放；私密同步時省略 `mine` |
| `skipFx()` | 本機點擊：播佇列下一個或關閉；不寫回 Firebase |
| `whenFxDone` | 只盯 `fxUntilRef`（播放結束時間），不等人點 |
| 接收 `fxEvent` | 非自己發出 → 空則播、忙則排；依 `privateTo`／`drunkMeta`／`swapMeta` 個人化 |
| `advanceAfterPassive` | 被動（含煉金術士）／保鏢／僕人：鎖定至換人；流程依時長推進，逾時強制換人 |
| 勝利視窗 | `gameOver` 後等終局動畫時長（狼月等）；非房主寬限等 fxEvent；不等 sticky 點擊 |
| 換人（`proceedToNext`） | 清除額外回合標記、`turnSeqRef += 1`、解除保鏢保護、`setCurrentTurnIndex`；快照以 `turnSeq` 判斷新舊 |
| 開新局 | 清空 `fxQueueRef`、目前 `fx`、相關 timer；非房主清空桌面並等房主寫入新 `gameState`；`gameState == null` 期間禁止寫回舊局 |

**動畫種類**：通用三拍、比大小、交換、醉漢、守夜人、保鏢、置於面前、僕人棄牌、煉金術士復活、拿一還一、月亮升起、狼月咬鏡頭、吸血鬼降臨、最終比點數等。
